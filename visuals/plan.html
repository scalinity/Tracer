What Claude generates, and what it costs

Claude writes the event trail for every synthetic specimen, a few showcase scenarios, and a search brief for every alert in the demo. Everything else, including fitting the models, is ordinary Python. The demo itself makes no live calls and holds no key: every Claude output is generated once, checked, and saved as a file.

The pilots and the full run have reported real usage, about $2.37 so far, entered under Spent. The jobs still to run are estimates. Change a model, a count or the batch setting and the totals follow.

How we keep the spend small

  • Pilot before scale. The 200-specimen pilot cost seven cents, and the full run started only after it passed the validator and a code audit.
  • Count first. The script calls count_tokens (free) before every job and stops if the estimate is over the job's budget.
  • Batch anything not interactive. The Batch API is half price. The full dataset and all search briefs go through it.
  • Use the small model for bulk. Haiku 5.5 writes the trails. Sonnet 5.5 writes the few pieces Karissa and the class will read closely. Opus is not needed.
  • Keep the shared instructions first. The rules, stage list and schema sit at the front of every request so the cached prefix is reused.
  • Low effort, no spare thinking. Set effort to low for trails. Thinking tokens are billed as output.
  • Structured output. A schema means replies parse, so retries stay rare. Two retries per specimen at most, then drop it.
  • Log every call to data/claude/usage.jsonl and type the real spend into the table above.
  • Hard stop. A spend limit in the Console, and a key that lives only in .env. It never goes into the repo, a message or the demo page.

Beat Tracer, the class activity

Everyone opens the demo link on a phone. A ward feed shows six specimens leaving collection. One goes silent. Tap the specimen you think is lost and press Call it. The sooner you call it correctly, the more warning you gave. A wrong call uses up one of your three alerts for the round.

After three rounds the page shows your median warning next to Tracer's on the same rounds. The point lands without a lecture: silence carries information, and a fixed threshold trades warning against false alarms.

  • The rounds come from the held-out test runs in the real bundle, never invented.
  • ?seed=18 in the link gives the whole room the same rounds, so people can compare answers out loud.
  • It runs in the browser with no server. Scores stay on the phone.
  • One round takes under a minute. Three rounds and the reveal fit in the four to five minutes the run of show allows, with time to ask who beat Tracer and how.
  • On a slow room, the presenter plays one round on the projector and asks for a show of hands.
  • An activity card at the top of the page lists three things to try and two questions to discuss, so the class can work through it in about 10 minutes.

What the demo page contains

  • The problem in sixty seconds, written by Karissa, with a glossary.
  • A live board ranked by expected harm, with the simple rule's verdict next to the model's.
  • A specimen timeline with a scrubber: risk, likely location, expected arrival, the window marker labelled with the event that stops the clock, and the moment the alert fires.
  • A threshold slider that shows warning time against alerts per shift for Tracer and the baseline.
  • Beat Tracer, as above.
  • A button on each specimen that opens the 3D view in that specimen's situation.
  • A short section on why the design is what it is: the survival model, the synthetic data, and warning time as the measure.
  • An honest limits section: the failures Tracer cannot see, and what real validation would need.

Seeing the silence in 3D

A pneumatic tube bench built from the same model as the board. The carrier is the truth. Hide it, and what is left is what the lab sees, which is nothing, and what Tracer infers, drawn as light along the tube. It is the opening image of the talk and the answer to "what does absence of data look like".

Press H for the compact view, T to hide the truth, L for the guided lesson. Open it in its own tab

Truth

The physical run and the carrier, placed where the specimen really is. Nothing in the lab sees this.

What the lab sees

Only scans. After the collection scan the tube run is dark until a receipt scan arrives, which is the gap the project exists for.

What Tracer infers

Risk of missing the window and the probability of each place the specimen could be, recomputed every minute from silence alone.

Every parameter in it is an assumption, and it says so on its help sheet. The fitted values from the pipeline replace them through one JSON file, without code changes.

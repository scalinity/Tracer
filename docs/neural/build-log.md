# Build log: v2 scenario data and TracerNet

A running diary of the build that `docs/neural/spec.md` describes: what was done, in what order, what was found, and every call made along the way. Newest entries last. Times are US Eastern. The pull-request record is `docs/ai-teaming-log.md`; this log is the day-by-day detail behind it.

Every number this work reports comes from synthetic data with no clinical review.

## Sunday, November 8

**9:03 PM.** Started at commit `8686475` with no pull requests open. Read the spec end to end, then `AGENTS.md`, `CLAUDE.md`, `docs/architecture.md` §4, §5, §7 and §9, and every file the spec's §1 cites: `src/pipeline/evaluate.py`, `store.py`, `src/models/risk.py`, `src/generator/briefs.py`, `validate.py`, `config.py`, the configuration files and both guard tests.

**Environment.** The project venv is Python 3.14.10 on an Apple M5 Pro (18 cores, 48 GB). `pip index versions torch` lists torch 2.15.0 for this interpreter on macOS arm64, so spec §7.11 takes its first branch: torch goes into `requirements.txt` and no separate Python 3.13 venv is needed. The suite collects 599 tests. `.env` holds all three key names (only their lengths were checked). HiPerGator is reachable over SSH with the class allocation, and is held in reserve for training if the Mac is too slow.

**9:15 PM, N0.** Committed the spec. `.env.example` now names `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` and `OPENROUTER_API_KEY`. `tests/test_no_key_in_site.py` now matches OpenAI keys (plain, project, service-account and admin) and OpenRouter keys, with a look-behind so words such as "risk-adjusted" do not match; adds OpenAI's API host, TypeSafe's API host and OpenRouter's API path to the host list; and checks each of the three keys' values against every tracked file. It gained ten cases and passes, including against the spec itself. Added tasks N0 to N11 to the plan, N0 to N9 under Gate C; the plan check passes.

**A shared contract before parallel work.** N1 (schema and prompt) and N3 (simulator) are built at the same time by separate agents, so `config/scenario.example.json`, the spec's worked example, was written first and both build against it. Writing it settled five gaps in spec §4.3, recorded as assumptions:

- Disruptions with no line, route, unit or instrument target use fixed ids: `lab_station` for an unattended station, `receiving` for short staffing and scanner downtime.
- A `mixed` unit sends by tube with its tube share, otherwise by its courier route if it has one, otherwise on foot.
- One shift clock per scenario, from `receiving.shift_pattern`, governs every day, evening and night field (staffing, station emptying, courier rounds). Under `7-19` the evening values are unused.
- `response` is `none` for every disruption type except a tube line outage, and `noticed_after_min` only matters for outages.
- Tasks N10 and N11 join no gate, since the spec puts only N0 to N9 under Gate C.

**9:16 PM.** N0 merged as #49. Five agents now build in separate git worktrees, none of which may commit: N3 the simulator, N1 the scenario schema, planner, prompt and validators, N2 the OpenAI client, ledger and runner (at the highest effort, since it guards the cap), and two pieces with no dependency on the others, TracerNet's network core (bins, rungs, loss, calibration) and the evaluation harness's core. torch 2.15.0 and Optuna 5.0.0 are installed; MPS works, though CPU wins on small matrices, as expected for a network of about 0.3 million parameters.

**Docs check before any API code.** All three model ids exist and the prices match the spec, with Batch and Flex at exactly half of Standard in every column. Three findings change the client: under OpenAI's default implicit caching a one-off prompt is billed at the cache-write rate (1.25 times input), so only the stable developer prefix earns its write back; Flex's capacity error is a 429 with no machine-readable code; and exhausted credit arrives as `credit_balance_exhausted`. The project must also allow the Flex tier, or every Flex request fails with a 400.

**HiPerGator.** The class allocation is 8 GPUs, 32 CPUs and 250 GB shared by the whole class. A 0.3-million-parameter network is limited by building its inputs, not by GPU arithmetic, so training starts on the Mac (18 cores) and HiPerGator is the fallback for running search trials or ablations in parallel.

**9:49 PM, N1.** The evaluation harness core landed first (59 tests; its vectorized scores and bootstrap reproduce `evaluate.py` exactly on the v1 held-out runs), then TracerNet's core (28 tests; 150,893 parameters at rung A and 317,901 at rung C, against the spec's 0.15 and 0.31 million). **10:14 PM, N2.** The client, ledger and runner landed. The O1 dry run builds the 72 real pilot requests (24 briefs on each of `gpt-6-luna` at low effort, `gpt-6.1-terra` at low and `gpt-6.1-sol` at medium) and prices them at $2.03 expected and $5.05 worst case against the $3.00 cap, sending nothing; requests the cap cannot cover are refused, never sent. Wiring found two problems before any money moved: the validator's layer names did not match the runner's, which would have paid for repairs of near duplicates, and the job configuration split the pilot by the main run's stratum shares instead of six per stratum.

**The simulator, second pass.** Feeding N1's code-random scenarios through N3's engine found specimens still sitting at their unit at the 7,200-minute horizon (a unit whose dispatch time has a median of 2 minutes and a 90th percentile of 170 has a very long tail). They produced invalid trails and would have dropped whole replicates. By the spec's definition such a specimen is never received, so it now ends open-ended, flagged `horizon_cut`. The plausibility check now simulates the full week instead of two days, since a two-day check never sees a disruption planned for later in the week; at 0.11 seconds per check the cost is negligible.

**10:18 PM, N3.** The simulator merged with its fixes (#53). Earlier entries' times are now taken from the commit history; the first drafts of three of them were estimates and ran up to 1 hour 40 minutes ahead of the clock.

**10:20 PM, pilot O1.** The first run stopped after 45 seconds on a seam the fakes never exercised: the runner passes a repair's reasons as a list, and the prompt expected one string. Nothing was lost. The 12 requests in flight had all completed, and their raw responses were on disk before the crash, so the resume settled each from its stored usage instead of keeping its worst case; no request was sent twice. After a one-line fix and a test through the real planner and prompt, the resume finished in 96 seconds: 69 of 72 brief-model pairs accepted, 7 repairs, 3 dropped, $0.60 of the $3.00 cap.

**The gate.** Every model passed G1 to G6. Real requests use about 10,500 input tokens (the dry run's local estimate was twice that) and 1,500 to 3,900 output tokens, so every model cost about half its estimate: `gpt-6-luna` low $0.0008 per accepted scenario, `gpt-6.1-terra` low $0.0072, `gpt-6.1-sol` medium $0.0175. Terra is the cheapest model within 5 points of the best on acceptance (96% against 100%) and adherence (100%); Luna was 8 points behind on acceptance. For the edge stratum the rule reads adherence on the edge briefs themselves, where Luna met 5 of 6 (83%) and Terra all 6, so Terra writes every stratum of the main run. The spec's count formula, floor($44 x 0.95 / $0.00715), gives 5,846 accepted scenarios, about 2.6 times the spec's planning figure of 2,250; the formula is followed as written, and the cap stops spending in any case.

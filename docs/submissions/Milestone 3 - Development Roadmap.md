## 1. AI Design Project Update (1-3 sentences)

Since Milestone 2, we inspected the open MIMIC-IV Clinical Database Demo. Across its 1,336 microbiology specimens, it confirmed that public hospital data records only specimen collection and the final result, with no events in between, so the modules will be developed on simulated specimen data. We also set up the project repository and documented the full system design.

## 2. AI Module Development

| Module Description | AI Task | Modeling Approach | Development Plan |
|---|---|---|---|
| Specimen status: judges whether a specimen between scans is on track, delayed, or likely lost or stalled | Tabular classification | Train a new model | Train on simulated specimen histories where each specimen’s true outcome is known. The model learns how long each leg normally takes for each specimen type, time of day, and lab volume, and outputs how likely a specimen is to be on track, delayed, or lost or stalled. |
| Arrival forecast: predicts when the next scan should occur | Tabular regression | Train a new model | Train on the same simulated histories, sharing the leg durations the status module learns, to predict when the next scan should occur with a likely and an outer bound. |
| Location estimate: infers where an unscanned specimen most likely is | Multiclass tabular classification | Train a new model | Train on simulated histories in which the true location of every specimen is recorded at every moment. The model uses tube-system events and elapsed time to output a probability for each possible location. |
| Search brief: tells the tech where to look first | Text-to-text generation | Context engineering with an LLM | Prompt an existing LLM with the outputs of the other three modules, the specimen details, and the stability reference table. A fixed template limits the note to where to look first, why, and how much time remains. No training data is required. |

## 3. Datasets (1-3 datasets)

| Dataset | Overview | Intended Use |
|---|---|---|
| Simulated Specimen Event Dataset | Planned size: 30 seeded runs of 7 simulated days, about 50,000 specimens. Five specimen types: urine, body fluid, bronchoalveolar lavage, culture swab, and tissue, each with its ordered tests, including anaerobic culture. Each record has timestamps for collection, tube dispatch and arrival, the wait on the lab counter, receipt, setup, and plating, plus the true location at every moment and outcome labels. Injected failures: lost in tube storage, stalled on the counter, misrouted to another station, and never sent. Generated by a simulation of one collecting area, one pneumatic tube system, and one microbiology laboratory. Stability windows come from the reference table below. All timing distributions are assumed and labeled as such, and none come from any institution’s records. The generator code will be published in the project repository. | Train and test the specimen status, arrival forecast, and location estimate modules, and power the interactive demo. |
| Specimen Stability Reference Table ([link](https://www.idsociety.org/practice-guideline/laboratory-diagnosis-of-infectious-diseases/)) | The stability window and transport condition for each of the five specimen types and each test ordered on them, one row per specimen type and test, each with its citation. Compiled from the IDSA and ASM 2024 Guide to Utilization of the Microbiology Laboratory for Diagnosis of Infectious Diseases. Transport swab manufacturer instructions serve as a secondary source for swab hold times ([link](https://www.copanusa.com/wp-content/uploads/2024/03/HPC030R05_PI-ESWAB-USA-2023.03.pdf)). | Sets the effective window behind the time remaining before recollection, which is the minimum across the specimen type and every test ordered on it. That value feeds the search brief and alert ranking. The table also parameterizes the simulator. |
| MIMIC-IV Clinical Database Demo v2.2 ([link](https://physionet.org/content/mimic-iv-demo/2.2/)) | 100 critical care patients with 1,336 microbiology specimens. The microbiology table records collection time and final result time only, a median of 80.1 hours apart, with no transport, receipt, or setup events. | Not used to train any module. It is used to test that the pipeline reads real microbiology records, and it serves as measured evidence that existing hospital data does not capture the interval Tracer monitors. That gap is why simulated data is the training source. |
